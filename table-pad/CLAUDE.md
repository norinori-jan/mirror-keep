# Nori のコーディングの決まり（coding-rules.md）

AI にコードを書かせるとき、毎回これを読ませる。「ダメ」と言ったことを二度言わなくてよくするためのファイル。

## 0. このファイルの使い方（先に読む）
### どこに置くか
- 本体は `C:\Users\norin\knowledge-base\coding-rules.md`（この1か所だけを直す）。
- アプリごとの作業フォルダ（例: `C:\Users\norin\ai-hub`）には、同じ内容を `CLAUDE.md` として写す。Claude Code は、起動したフォルダの `CLAUDE.md` を毎回自動で読む。
  - 写しは GitHub に上げない（`.git\info\exclude` に書いて、commit の対象から外す）。
- 本体を直したら、写しも作り直す（配置ブロックをもう一度貼る）。

### 3つの使い方
1. **PC の Claude Code**: アプリのフォルダで `claude` を起動すると、`CLAUDE.md`（この内容）を読んだ状態で始まる。「この決まりに従って○○を作って」と言うだけでよい。
2. **チャットの Claude**: 新しい会話の最初に、このファイルを貼る（または「coding-rules.md の通りに」と言って添付する）。
3. **ai-hub（iPhone）**: 💻 コードモードの「ルール帳」に、第2章の「ダメ／よい」を入れる。ai-hub は、答えるたびにルール帳を読む。

### 育て方
- AI が決まりを破ったら、第2章に1行足す（「ダメ」に書く）。直接言った言葉のまま書く。
- 「これでよい」と思った書き方は「よい」に足す。
- 迷った行は消す。長すぎると守られない。目安は全体で 100 行以内。
- 守ってほしい順に、上から書く。

### 守られているかの確かめ方
- 出力を受け取ったら、第5章のチェックを上から見る（1分）。
- 破られていたら、その行を太字にして「これを守って」と言い直す。

## 1. 前提（あなたの環境）
- iPhone が中心。PC は git 作業用（Windows PowerShell）。
- アプリは GitHub Pages で動く、**単一ファイルの HTML（PWA）**。
- GitHub のユーザー名は norinori-jan。リポジトリごとに、アプリ名のフォルダを PC に持つ。
- 日本語で、短く、具体的に答える。

## 2. ダメ／よい（ルール帳に入れる行）
### ダメ
- ビルドツールやフレームワーク（React / Vue / npm など）を使う案。単一ファイルの HTML だけで作る。
- 鍵・トークン・パスワードの値を、コードにもチャットにも書く。
- PowerShell に `<ここに入れる>` のような穴あきや、説明の文章の行を混ぜる。
- `if (…) { … }` の次の行に `else` を置く（貼ると別のコマンドとして実行されて失敗する）。
- 「保護」「機密」のメモを、AI に送る処理を作る。
- 既存リポジトリのファイル名を、確かめずに変える。
### よい
- アプリは単一ファイルの HTML の PWA（GitHub Pages で動く。iPhone でも動く）。
- ファイルは「アプリ名__ファイル名」の名前で渡す（`index.html` や `sw.js` を素のままにしない）。
- PowerShell は、貼ってそのまま動く**1ブロック**（ファイルを探す → フォルダ／リポジトリが無ければ作る → コピー → commit → push）。
- 複数行の PowerShell は `& { … }` で全体を包む。
- 既存リポジトリのファイル名は先に確認して合わせる（例: flow-mind は `flow-mind-sw.js`）。
- 説明は、先に「形」、次に「部品の意味」、次に「例」、最後に「よくある間違い」。

## 3. 渡し方（コードを出すとき）
1. ファイルは `アプリ名__ファイル名` で、ダウンロード（Downloads）に置ける形で渡す。
2. 最後に、**コピーするコードブロックを1つだけ**付ける。ブロックの中に説明の文章は入れない。
3. commit メッセージの最後に、AI の共作の行（Co-Authored-By など）を付ける。
4. 試していない部分は「未テスト」とはっきり書く（特に PowerShell）。

## 4. コードの書き方
- 外部の CDN・ライブラリを増やさない。必要なら理由を先に言う。
- localStorage / IndexedDB は、読み書きを try/catch で包む（iPhone のプライベート環境で例外が出る）。
- iPhone のホーム画面アプリと Safari は、保存領域が別。設定の入力が必要になる場合は、画面に説明を出す。
- 通信は、タイムアウト（AbortController）と、`res.ok` の確認を付ける。
- 表示用の文字列に入れる値は、HTML として解釈されないように escape する。
- ボタンは 44px 以上。`viewport-fit=cover` と `env(safe-area-inset-*)` で、ノッチとホームバーを避ける。
- Service Worker は、HTML は通信優先、画像などは保存優先。キャッシュ名に版を入れる。
